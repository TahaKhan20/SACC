# AP Invoice Triage Agent (Plain Python)

A production-ready pipeline that triages AP invoices using the SAP Document AI (Document Information Extraction) mock APIs generated by the SACC project. No LangGraph dependency — just plain Python function chaining with two if/else branches.

## Files

| File | Description |
| --- | --- |
| `triage_agent.py` | Main LangGraph triage agent script |
| `requirements.txt` | Python dependencies |
| `.env.example` | Environment variable template (copy to `.env`) |

## API Mapping

The triage agent calls the SACC mock FastAPI server at `http://localhost:8000` (configurable via `SACC_API_BASE_URL`).

### Document AI API (`document_information_extraction_api_v2`)

| Step | API Call | Entity Set | Method |
| --- | --- | --- | --- |
| 1. Upload document | `POST /api/services/document_information_extraction_api_v2/entities/Documents` | `Documents` | POST |
| 1. Upload file | *MISSING* -- `Files` entity is read-only (insertable=false) | `Files` | Filler |
| 2. Upload schema | `POST /api/services/.../entities/SchemaVersions` + `SchemaEntities` | `SchemaVersions`, `SchemaEntities` | POST |
| 3. Load schema | `GET /api/services/.../entities/SchemaVersions/item` + `SchemaEntities` | `SchemaVersions`, `SchemaEntities` | GET |
| 4. Process document | *MISSING* -- no processing trigger in mock | -- | Filler |
| 4. Get extraction | `GET /api/services/.../entities/DocumentEntities` | `DocumentEntities` | GET |
| 12. Load detailed schema | Same as Step 2/3 | `SchemaVersions`, `SchemaEntities` | POST/GET |
| 13. Extract detailed | Same as Step 4 | `DocumentEntities` | GET |

### Supplier Invoice API (`OP_API_SUPPLIERINVOICE_PROCESS_SRV`)

| Entity Set | Key Fields | Notes |
| --- | --- | --- |
| `A_SupplierInvoice` | `SupplierInvoice`, `FiscalYear` | Header fields |
| `A_SupplierInvoiceItemGLAcct` | `SupplierInvoice`, `FiscalYear`, `SupplierInvoiceItem` | Line items (insertable=false in mock) |

## Missing APIs (Fillers)

The following APIs are not available in the SACC mock and are filled with placeholder logic:

1. **File Upload** -- The `Files` entity has `insertable=false`. Real SAP Document AI requires a multipart/form-data upload to a separate endpoint. The filler generates a placeholder GUID.

2. **Document Processing Trigger** -- The mock has no endpoint to trigger document processing (OCR/extraction). The filler creates a `DocumentVersion` record and simulates a COMPLETED status.

3. **Line Item Extraction** -- Child `DocumentEntities` with `parent_ID` relationships for line items are not populated in the mock. The filler simulates a single line item from header data.

## Workflow

```
START -> upload_document -> upload_classification_schema -> load_classification_schema
  -> classify_with_document_api -> determine_document_type
  |
  +-- (SUPPORTING_DOCUMENT / OTHER) --> review --> build_triage_result --> END
  |
  +-- (INVOICE / CREDIT_NOTE / STATEMENT)
        --> classify_company
        |
        +-- (NO_MATCH) --> review --> build_triage_result --> END
        |
        +-- (MATCH / UNCERTAIN)
              --> classify_direct_intercompany --> classify_invoice_type
              --> select_detailed_schema --> load_detailed_schema
              --> extract_detailed_fields --> validate_extraction
              --> build_triage_result --> END
```

## Usage

```bash
# 1. Start the SACC mock server (from parent directory)
cd /path/to/SACC && python main.py

# 2. Install dependencies
cd dev && pip install -r requirements.txt

# 3. Copy and configure environment
cp .env.example .env  # Edit as needed

# 4. Run the triage agent
python triage_agent.py /path/to/invoice.pdf
```

## TriageResult Output

The agent returns a strict JSON `TriageResult` containing:

- `document_type`: INVOICE | CREDIT_NOTE | STATEMENT | SUPPORTING_DOCUMENT | OTHER
- `company_classification`: MATCH | NO_MATCH | UNCERTAIN
- `direct_intercompany`: DIRECT | INTERCOMPANY | UNKNOWN
- `invoice_type`: FUEL | CHARTER | SERVICE | OTHER
- `extracted_header_fields`: dict of extracted header field values
- `line_items`: list of line item dicts
- `confidence`: overall extraction confidence (0.0-1.0)
- `evidence`: list of human-readable evidence strings
- `review_required`: boolean
- `review_reason`: string or null
